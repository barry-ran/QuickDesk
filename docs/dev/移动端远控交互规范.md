# 移动端远控交互：Web / Android 共同行为

## Review 结论

Web 的远控页使用原生 JavaScript（Vue 只负责入口），Android 主控使用 Flutter；两者不是同一个 UI 运行时。原有注释宣称体验一致，但实际存在：

- Android 两指距离大于 12px 就进入 pinch，普通双指滚动几乎不可达；Web 放大后不再滚动。
- Web pinch 围绕画面中心而不是手指焦点缩放；两端缩放后的指针灵敏度过高。
- 两指结束后剩余手指会重新成为点击，导致误操作；取消及生命周期清理不足。
- Web 软键盘监听器在重连后累积；App 在 IME 候选组合过程中发送未提交文本。
- 移动工具栏与隐藏手势缺乏清楚说明，窄屏下不易发现操作。

## 交互决策

采用**触控板优先**，不把手机屏幕的触点误当成远程桌面点击坐标。小屏幕上，手指不遮住实际点击对象；光标是唯一点击定位依据。保留桌面 Web 的鼠标和实体键盘路径，不修改 Remoting 内核。

| 动作 | 两端共同语义 |
| --- | --- |
| 单指滑动 | 相对移动光标；远程坐标增量 = 逻辑像素增量 × 2.5 / 当前缩放；限制在远程桌面范围 |
| 单击 / 双击 | 在光标处发送一次 / 两次标准左键按下、释放 |
| Drag 按钮后滑动 | 显式准备拖拽，超过移动阈值才按下左键；抬起释放，再次点 Drag 取消 |
| 单击后再次按住滑动 | 第二次触摸超过 8px 开始左键拖拽；抬起或取消立即释放 |
| 长按 500ms | 在光标处右键；不追加左键点击 |
| 两指平移 | 任意缩放级别滚动远程内容，支持水平和垂直；不是平移视口 |
| 两指捏合 | 1–5 倍焦点缩放；进入 pinch 后可移动焦点平移视口，不发送滚轮 |
| 放大后移动光标 | 光标接近边缘时视口自动跟随；Fit 恢复全屏适配 |
| Keyboard | 调起系统输入法，仅发送已提交文字；保留退格/回车及快捷键入口 |
| Help | 随时查看手势，不以用户猜测隐藏操作为前提 |

两指手势先观察意图：距离变化达到 `max(8px, 初始距离 × 5%)` 优先锁为缩放，否则中心位移达到 8px 锁为滚动。一次手势中不在两种模式之间跳转。两指结束的残余手指、第三指介入及取消都不能产生额外点击；必须全部抬起才能开始新手势。滚轮系数为每逻辑像素 3 个 delta 单位，ticks 为 delta/40，沿用现有协议方向。

缩放的焦点公式为 `newTranslate = focal - viewportCenter - (startFocal - viewportCenter - startTranslate) × newScale/startScale`。平移范围基于实际 contain 后的视频内容，不基于黑边。分辨率、横竖屏和键盘视口变化重新限制坐标；会话离开/取消释放正在拖拽的鼠标。

## 维护与验收

跨语言不强行共享运行时代码；共享 `test/fixtures/mobile-gestures.json` 的行为用例，并由 Node 与 Flutter 测试消费。增加行为时同时更新两端及该契约，避免只改注释。

自动化入口：

```sh
cd WebClient
npm install
npm test
npm run build
npx playwright install chromium
npm run test:e2e:mobile
# 已安装系统 Chromium 时：QD_BROWSER_EXECUTABLE=/usr/bin/chromium npm run test:e2e:mobile
cd ../quickdesk-android
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

浏览器仿真验证手势状态机、真实 DOM 变换及窄屏布局，不等同于手机真机。发布前仍需 Android 真机 + iOS Safari / Android Chrome 与实际远程主机端到端验收：中文/日文输入法候选、emoji、软键盘退格、横竖屏与键盘反复开关、应用切后台和网络中断时释放拖拽、不同 DPI/分辨率和系统双击设置。没有连接真机/远程主机时不得标注这些检查通过。
