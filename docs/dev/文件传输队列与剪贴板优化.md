# 文件传输队列与剪贴板优化（Qt 层）

## 范围

在现有 native messaging 文件传输命令上增加调度，不修改 quickdesk-remoting、
二进制版本、传输协议或服务端。Aspia 仅作为交互设计参考，没有移植其 GPL 源码。

- 对话框、拖拽和 Ctrl+V 共用每连接串行上传队列。
- UI 使用本地 taskId；传输关联另存原始 connectionId 和 native transferId。
- 等待中重复粘贴同一本地规范路径不会重复派发；不同目录的同名文件可以排队。
- 目录明确提示暂不支持，不进行隐式打包、递归上传或远端解包。
- 已下载文件只能经用户点击“复制文件”写入本地剪贴板；不自动覆盖剪贴板。
- 复制前检查完成状态、文件存在且可读、规范路径仍在请求的下载目录内。
- 不实现远端虚拟文件、OLE 延迟渲染、原生目录粘贴、暂停/断点续传或远端目标目录选择。

## 取消和关联边界

现有公开 Qt 合约没有 caller requestId，也没有被证实的独立取消确认事件。
因此一次只向同一 connectionId 派发一个上传：

1. 未派发任务直接取消，不发网络命令。
2. 已派发但未得到 transferId：记住取消意图，取得 ID 后只发一次原有 cancel 命令。
3. 已发取消请求：保持槽位，直到传输终态或连接结束。15 秒无结果转为
   “结果未确认”，提示重连；不假称远端已取消，也不让下一文件复用模糊槽位。
4. Complete 先到视为完成；Error 以实际错误终结当前任务（不把一般错误称作取消成功）。退休的非空 transferId 不再接受事件。
5. 没有 transferId 的错误/完成无法证明哪个任务结束；保留不确定状态、停止该会话
   后续上传并提示重连，不将无标识结果猜给任务或假称完成。
6. 主动/被动断连、messaging 替换/故障、连接列表失联都会结束旧代次。
   迟到事件不会复活旧任务。重新连接产生新的 connectionId。

注意：这不是对 native 二进制内部写入、取消回执或半成品清理的保证。
不能仅靠 Qt 前端保证远端部分文件删除、覆盖策略或目的路径安全。
不擅自删除远端文件；取消不确定时用户应检查接收端文件。

## 验证

独立 Qt 测试不链接/启动 remoting，不进行真实远程文件传输：

```sh
cmake -S test/file-transfer -B build/file-transfer -DCMAKE_PREFIX_PATH="$QT_ROOT_DIR"
cmake --build build/file-transfer --config Release
ctest --test-dir build/file-transfer -C Release --output-on-failure
node --test test/file-transfer/qml_contract_test.mjs
```

Qt 测试覆盖多连接同名文件、同连接不同路径同名队列、未获 ID 取消、取消超时、
终态竞争、无 ID 错误隔离、断连重连迟到事件、重复提交、目录/无效路径、空文件、
超过 4 GiB 的进度计数、确认下载后显式剪贴板写入及失效/越界下载路径。
大文件计数采用模拟事件，不分配大文件内容。

Node 测试运行从实际 QML 提取的 JS handler，验证模型关联及快捷键交互契约；
它不等价于运行 QML 引擎或真人 Windows Explorer/Finder 操作。

Windows 和 macOS 原生 CI 在完整应用构建前运行上述测试。
人工验收还需测试真实 native 版本的取消终态、断网半成品、Explorer 中文/长路径文件、
切标签、焦点丢失、剪贴板被其他程序替换，以及下载完成后重连再复制。
